<p>挑家庭宽带线路，最省事的办法不是听推荐，而是拿一张清单逐项打勾。打勾的过程看着笨，但它能把"感觉还行"变成"这几条通过、那几条不通过"，后面批量续费时就有依据，不会又踩回共享 IP 那种速度忽快忽慢的坑。下面这份清单按顺序排，前一项目没通过就别做下一项，省时间也省钱。</p>

<h2>一、清单开头：先明确要测哪几项</h2>
<p>没有测试项，试水就会变成"用几天看看"，结论全凭印象。先把要测的东西定下来。</p>
<h3>四个必测项</h3>
<p>出口归属、地址稳定性、速度曲线、会话连续性。前两项决定"这条线像不像家宽"，后两项决定"用起来顺不顺"。四项之外的东西，比如客服响应、后台易用度，属于加分项，不进这张清单。</p>
<h3>测多久算够</h3>
<p>至少三天，最好覆盖一个完整工作周。每天分三个时段测：本地上午、本地晚间高峰（20 点到 23 点）、凌晨低谷。三个时段的速度差异，比单次测速数字有信息量得多。</p>

<h2>二、第二项：干净的判定，用字段说话</h2>
<p>干净与否不能靠感觉，逐条查，查完打勾或打叉。</p>
<h3>查归属与 ASN</h3>
<p><code>curl https://ipinfo.io/1.2.3.4/json</code> 看 org 与 asn。家宽运营商的描述里常带 telecom、broadband、cable、fiber 之类字样；出现 hosting、cloud、vps、datacenter，直接判不合格。再上 bgp.tools 看这个 ASN 的地址块规模，一个 /24 被切成几百个客户用，说明邻居密度高。</p>
<h3>查稳定性</h3>
<p>连续三天每 30 分钟请求一次 ipinfo，记录返回的 IP。独享静态线三天应只有一个值；出现多个值说明在池里轮换，属于动态线，用途要相应调整。这个测试用一条 shell 循环加日志就能跑，成本几乎为零。</p>
<h3>查风险标记</h3>
<p>用 ipapi.is 或 scamalytics 查，被标为 proxy、vpn、datacenter 的一律不合格。这类标记不一定影响所有平台，但会显著提高被要求验证的概率，试水阶段没必要留这种隐患。</p>

<h2>三、第三项：共享 IP 的速度为什么忽快忽慢</h2>
<img src="/tp.png" alt="家庭宽带线路共享与独享出口的速度曲线对比">
<p>很多人把"忽快忽慢"归因于线路质量差，其实多数是共享导致的带宽争抢。</p>
<h3>带宽被分走的机制</h3>
<p>一条出口的总带宽固定，同时使用的人越多，每人分到的越少。共享池里如果有人跑大文件、做视频上传，其他人的页面加载就会明显变慢。表现很有规律：白天正常、晚间高峰卡顿、凌晨又恢复。如果你的速度曲线呈现这种作息特征，基本可以判定是共享。</p>
<h3>怎么区分共享与线路本身差</h3>
<p>看两个指标：一是速度的方差，共享线的下行速度在不同时段能差三到五倍，线路差则是全程都低；二是丢包的时间分布，共享拥塞集中在高峰，线路故障的丢包是随机的。区分清楚才好做决策：共享就换成独享，线路差就直接换服务商，别在一条差线上调参数。</p>
<h3>测速的具体做法</h3>
<p>用 <code>curl -o /dev/null -w "%{speed_download}\n" 测试文件地址</code> 连测五次取中位数，比网页测速稳定；延迟用 <code>mtr -rwzbc 100 目标地址</code> 看 P95 与丢包率。判定阈值参考：丢包连续一小时超过 1% 不合格，P95 延迟超过 350 毫秒要记录，下行中位数低于 20 Mbps 不适合带图片上传的场景。</p>

<h2>四、第四项：什么条件才允许批量续</h2>
<p>这一项是清单的闸门，过不了就别续，多等一周比多花一年便宜。</p>
<h3>三个放行条件</h3>
<p>试水的三到五条线连续 14 天无超过十分钟的断线；高峰时段速度中位数达到平时的七成以上；订阅扣费或关键操作一次通过没有反复失败。三条同时满足才放行，缺一条就继续观察。</p>
<h3>两个否决条件</h3>
<p>一是同一批次里出现两条以上被风险库标记的地址，说明这个批次整体不干净，退掉换批次；二是服务商无法提供退款或按月折算条款，年付一律不签。这两条是硬否决，不因价格便宜而放宽。</p>
<h3>续费按批次走</h3>
<p>先续六成，观察一周，稳定后补齐。每批新线到货都要重新跑第二项的四个检查，别因为"同一家"就跳过。批次之间的质量差异是行业常态。</p>

<h2>五、把清单压成一页纸</h2>
<p>清单太长没人用，最后一页就够：左边一列检查项，中间一列阈值，右边一列"通过打勾、不通过写原因"。每次进新线，打印一份手填，填完拍照存档。</p>
<h3>谁来打勾</h3>
<p>由实际使用的人打勾，不要让采购代填。打勾的人要对结果负责，这样后续出问题时，能追到是哪一项当时没看。这一条比清单本身更重要。</p>

<h2>常见问答</h2>
<h3>家里自己拉的宽带能当出口用吗？</h3>
<p>答：技术上可以，但要看运营商是否给公网地址、上传带宽是否够、以及是否允许对外提供访问。多数家宽是动态地址加 NAT，稳定性不适合长期挂账号，仅适合个人少量使用。</p>
<h3>共享 IP 一定不能用吗？</h3>
<p>答：不是绝对。一次性查询、临时抓取这类用途完全够用。问题在于把它用在长期号、订阅扣费、客户演示上，速度波动和邻居影响都会成为变量。</p>
<h3>测速要不要用平台自带的测速页？</h3>
<p>答：可以看，但别只信它。平台测速页选的节点、并发数都不一样，结果波动大。用固定目标文件加 curl 连测取中位数，再配 mtr 看路径质量，两组数据互相印证更可靠。</p>
<h3>三条线都合格，能不能只续一条？</h3>
<p>答：可以，但要按用途续。先续承担核心业务的那些号对应的线，边缘号继续按量。省钱的关键不是少续，而是别把独享线用在不需要独享的地方。</p>
